# `plans/test-designs/ST-n.yaml`: the frozen oracle

- **Owner:** `qa-derive` (it is the only writer; `test-engineer` is write-denied).
- **Machine schema:** [test-design.schema.json](test-design.schema.json).
- **Format:** the same YAML subset as the other plan files (no anchors, tags or multi-line flow).

```yaml
story: ST-12
ac_hash: "sha256:4be1…"            # the story's AC hash at design time; a mismatch = stale design
designed_by: qa-derive             # informational; identity comes from the ledger entry
design_entry: ENTRY-1042           # REVIEWED (testability ACCEPT) ledger entry
inputs:                            # partitions AS SPECIFIED; values are generated by boundary_values.py
  amount:   {type: number, min: 0.01, max: 10000, precision: 2, required: true, nullable: false, source: "ST-12/AC-1"}
  currency: {type: enum, enum: [EUR, USD], required: true, nullable: false, source: "ST-12/AC-1"}
  memo:     {type: string, min_length: 0, max_length: 140, required: false, source: "ST-12/AC-2"}
scenarios:
  - id: ST-12/SC-1
    ac_refs: [ST-12/AC-1]
    technique: BVA
    tier_hint: unit
    given: "a funded EUR account"
    when: "a transfer of each boundary amount is submitted"
    then: "amounts 0.01 and 10000.00 are accepted; 0.00 and 10000.01 are rejected with error AMOUNT_OUT_OF_RANGE"
    expected:
      - {partition: "amount=min..max", outcome: "accepted"}
      - {partition: "amount<min | amount>max", outcome: "rejected", error: "AMOUNT_OUT_OF_RANGE"}
    data: {vary: [amount], hold: {currency: EUR}}
  - id: ST-12/SC-2
    ac_refs: [ST-12/AC-3]
    technique: state-transition
    tier_hint: component
    given: "a transfer in status PENDING"
    when: "the user cancels it"
    then: "status becomes CANCELLED and a TransferCancelled event is emitted"
    expected:
      - {outcome: "status=CANCELLED"}
      - {outcome: "event TransferCancelled{transferId}"}
  - id: ST-12/SC-3
    ac_refs: [ST-12/AC-3]
    technique: state-transition
    kind: negative
    given: "a transfer in status SETTLED"
    when: "the user cancels it"
    then: "the request is rejected with 409 TRANSFER_NOT_CANCELLABLE and the status is unchanged"
gaps:                              # each one is also a QUESTION entry in the ledger
  - id: ST-12/GAP-1
    question: "Is memo nullable (null vs omitted)?"
    proposed: "treat null as omitted (accepted)"
    question_entry: ENTRY-1043
    blocking: false
```

## Rules the schema and lint enforce
- Scenario IDs `ST-n/SC-n` are unique and **never reused**. A removed scenario is marked
  `retired: true` with a reason. It is never deleted, because tests reference these IDs.
- Every `ac_refs` entry exists in the story. Every `automated` AC is referenced by at least one scenario.
- At least one scenario has `kind: negative`, except for DOCUMENTATION and SPIKE.
- `expected` describes **observable** outcomes: status, error code or message key, emitted event,
  persisted state, rendered element. It never describes internal calls.
- `source: implementation-finding` scenarios carry the finding entry ID and qa-derive's REVIEWED entry.
- There is no `status` field. Freshness is derived by comparing `ac_hash` to the story's current hash.
