# Test Data Management


## Purpose
Reproducible tests with data that carries no privacy or security risk.

## When this applies
- New tests need data, or existing tests fail because of shared or leftover data.
- Anyone proposes using a production dump or real customer records.

## Preflight
See [standard-preflight](../../../workflow/stage-preflight/reference/standard-preflight.md).
1. **Workspace.** Resolve repo roles `[app, tests, infra]`. If found, record it as FACT `repo@sha`. If ambiguous, raise one QUESTION with ranked candidates. If missing, workspace-resolver offers local creation or a `repo-request.yaml`. If there is no test framework for this tier, that is **Mode C, as its own `TEST_AUTOMATION` story** ([suite-authoring](../../test-implementation/suite-authoring/SKILL.md)). It is never scaffolded inside a feature story.
2. **Frozen test design** (`plans/test-designs/ST-n.yaml` or `.feature` at the story's current `ac_hash`): SATISFIED. If it's missing, offer **BACKFILL** (DESIGN via qa-derive, [test-case-design](../../test-design/test-case-design/SKILL.md)) or **characterization mode** ([ADR 0004 §3](../../../../docs/adr/0004-workflow-stages-and-workspace.md)): tests tagged `characterization`, an ASSUMPTION "current behaviour is intended" recorded, and they never count as AC verification or VERIFIED. If the `ac_hash` is stale, BLOCK.
3. **Environment.** The target is either an ephemeral preview (the agent may seed it) or shared staging (CI-only seeding). The seed scripts and the environment's readiness endpoint must resolve. The preflight for data *generation* is in [test-data-synthesis](../../test-data/test-data-synthesis/SKILL.md).

Never proceed on a missing input silently.

## Procedure
1. **Prefer generated over stored**: factories/builders (`factory_boy`, `FactoryBot`, `@faker-js/faker`
   with a fixed seed, `Instancio`) that create exactly what each test needs.
2. **Isolate per test**: unique identifiers per test; transactional rollback fixtures for unit/integration
   tests; ephemeral databases via Testcontainers for integration suites. No reliance on a shared,
   long-lived "QA database" state.
3. **Seed via APIs** in E2E tests, not via the UI and not via direct writes that bypass invariants.
4. **Production data is off limits for agents.** Touching production data is one leg of the Rule of Two
   (plan §5.9); a session that also reads untrusted input (issue text, logs) must not have it. If
   realistic distributions are needed, a human-run pipeline produces a masked or synthetic dataset
   (e.g. tokenized PII, Synthetic Data Vault-style generation); agents consume only its output.
5. **Golden files** (expected outputs) live beside tests, are regenerated by an explicit command, and
   changes to them get reviewed like code.
6. **Time and randomness** are inputs: inject a clock and a seed; print the seed on failure.
7. **Secrets** in fixtures are fakes with an obviously fake format (`sk_test_FAKE...`) and allow-listed in
   the secret scanner by path, not by disabling rules.

8. **Generation is a separate skill.** Choosing partitions, generating boundary values, batching data questions
   and handling secrets by reference are covered in [test-data-synthesis](../../test-data/test-data-synthesis/SKILL.md).
   This skill covers the *lifecycle* of data in environments.

### Environment data lifecycle (live and E2E tiers)
9. **Namespace every run.** Each entity a run creates carries the run ID: `e2e-${RUN_ID}-alice@example.com`,
   `ORD-${RUN_ID}-0001`. Parallel workers and re-runs never collide, and teardown can find what it owns.
   Use idempotent seed calls (PUT/upsert by namespaced key), so a retried seed doesn't duplicate data.
10. **Seed through supported paths.** Use the public or admin API, or the CI-run seed scripts
    (`seed-staging-users` in [required-secrets](../../test-data/test-data-synthesis/reference/data-resolution-protocol.md)).
    Never write directly to the DB of a shared environment, and never seed through the UI.
11. **Health-check before the suite.** Probe the environment's readiness endpoint and required seed accounts. If it
    isn't ready, the result is `ENVIRONMENT_NOT_READY` (a STOP/RETRY failure class), not a red test run.
12. **Tear down and verify.** `afterEach`/`afterAll` deletes the run's namespace. A final check queries for leftovers
    with the run prefix and fails the job if any remain. A nightly janitor removes namespaces older than 24 hours from
    crashed runs.
13. **Who runs where.** Agents seed and tear down only **ephemeral preview environments** (`WORKSPACE_WRITE`
    scope). Seeding shared staging is an `EXTERNAL_MUTATION`, done only by CI jobs running as the SYSTEM identity.

## Outputs
- Fixtures/factories (`REPO_WRITE`). Data-plan proposals → `PROPOSAL`. Any request for production data → `QUESTION` to a human.

## Enforcement
**Enforced** (partial) — some rules are structural, others are guideline only.

The production-data restriction is enforced by Rule-of-Two session scoping and per-role tool scoping (plan §5.6).
The rest is guideline only.
